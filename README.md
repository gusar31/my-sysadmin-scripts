# Мониторинг ресурсов Linux

Учебный сервис на Bash собирает показатели системы и дописывает их в `monitor.log` с временными метками. Первый замер выполняется сразу, затем между замерами выдерживается пауза 10 секунд.

## Метрики

- `free -h` — использование оперативной памяти и swap.
- `df -h` — занятое и свободное место файловых систем.
- `uptime` — время работы системы и средняя нагрузка.
- `nproc` — количество доступных процессоров.
- `/proc/loadavg` — нагрузка за 1, 5 и 15 минут и сведения о задачах.

Скрипт проверяет наличие команд и возможность записи в журнал. При ошибке отдельного замера сообщает о ней и продолжает сбор остальных показателей; при критической ошибке записи завершает работу.

## Архитектура сервиса

Сервис развёрнут в Ubuntu 22.04 на виртуальной машине VirtualBox. Доступ к VM выполняется по SSH с ключом.

Dockerfile описывает окружение скрипта и Python HTTP-сервера, а Docker Compose — контейнер `my-app`, порты и подключение каталога журнала. Журнал хранится вне контейнера и сохраняется при его пересоздании.

Python HTTP-сервер отдаёт журнал на порту 8080. Nginx работает на VM как reverse proxy: принимает HTTPS-запросы на порту 443 и передаёт их контейнеру. HTTP-запросы на порт 80 перенаправляются на HTTPS с кодом 301.

Для HTTPS через OpenSSL создан самоподписанный сертификат на 365 дней. Он обеспечивает шифрование, но требует отдельного подтверждения доверия клиентом. Приватный ключ хранится на VM и не входит в репозиторий.

Systemd-служба `my-app` запускает контейнер после Docker при загрузке VM, позволяет управлять его состоянием и перезапускает при ошибке.

## Учебное хранилище

На VM отдельно настроены RAID 1 и LVM на loop-устройствах — виртуальных дисках, созданных из файлов.

- RAID 1 объединяет два файла по 512 МиБ в зеркальный массив `/dev/md0`, смонтированный в `/mnt/raid`. Он демонстрирует дублирование данных между участниками.
- LVM использует третий файл: группа `vg_data` содержит том `lv_logs` размером 200 МиБ, смонтированный в `/mnt/logs`. Он демонстрирует гибкое распределение дискового пространства.

LVM создан отдельно от RAID. Журнал контейнера хранится в каталоге проекта `logs`, а учебные тома не подключены к контейнеру. Все образы дисков лежат на одном виртуальном диске, поэтому такой RAID не защищает от его отказа.

Метрики в контейнере зависят от его окружения и могут частично отражать ресурсы всей VM. Пример замеров приведён в `sample_output.txt`.
