# Мониторинг ресурсов Linux

Скрипт каждые 10 секунд дописывает показатели системы в `/home/ubuntu/resource-monitor/monitor.log`. Каждый блок начинается с временной метки вида `--- 2026-10-25 15:32:39 ---`. Существующее содержимое журнала сохраняется.

## Собираемые показатели

- `free -h` — использование оперативной памяти и swap.
- `df -h` — занятое и свободное место файловых систем.
- `uptime` — время работы системы и средняя нагрузка.
- `nproc` — число процессоров, доступных текущему процессу.
- `/proc/loadavg` — нагрузка за 1, 5 и 15 минут, число выполняемых/существующих задач и PID последнего созданного процесса.

Перед выводом каждой команды записывается её название, чтобы журнал было проще читать. Временная метка использует часовой пояс Linux-машины.

## Запуск

Скрипт предназначен для Linux с Bash и файловой системой `/proc`, например Ubuntu 22.04. Запускайте его от пользователя `ubuntu`, имеющего доступ к указанному каталогу:

```bash
bash script.sh
```

Интервал `N=10` и абсолютный путь `LOG_FILE` заданы в начале скрипта. Интерактивный ввод не нужен. При переносе к другому пользователю измените путь `LOG_FILE` на доступный ему абсолютный путь.

Первый замер выполняется сразу; после каждого блока скрипт ждёт 10 секунд. Время выполнения самих команд добавляется к интервалу между началами замеров.

Просмотр журнала из другого терминала:

```bash
tail -f /home/ubuntu/resource-monitor/monitor.log
```

Остановка скрипта — `Ctrl+C`. Сигнал `SIGTERM` также корректно завершает мониторинг с кодом 0 и сообщением в терминале.

## Обработка ошибок

- Перед запуском проверяется наличие необходимых команд. Если команда отсутствует, скрипт сообщает её имя и завершается с кодом 1.
- Каталог журнала создаётся автоматически. Если его невозможно создать или журнал нельзя открыть для дописывания, скрипт выводит ошибку и завершается с кодом 1.
- Если отдельная команда сбора завершается с ошибкой, её сообщение и код возврата попадают в журнал, а краткое уведомление — в stderr. Сбор остальных показателей продолжается.
- Если `/proc/loadavg` невозможно прочитать, ошибка фиксируется в журнале и stderr; мониторинг продолжается.
- Неожиданные ошибки, включая ошибки записи при заполнении диска, останавливают скрипт с кодом 1 и сообщением в stderr. При недоступном журнале само сообщение об ошибке может сохраниться только в терминале.

Журнал растёт, пока работает скрипт; автоматическая ротация не реализована. Запускайте одну копию скрипта, чтобы блоки разных процессов не перемешивались.
